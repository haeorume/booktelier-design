# 1차 MVP 교정표 (11.18 기준)

시트 문서끼리 어긋나는 곳을 1차 동안 임시로 정해 둔 표예요. 어긋나면 **이 표가 이겨요**. 시트가 고쳐지면 그 줄을 지워요(사람이).
'기계 검사' 칸에 R 번호가 있는 줄은 `scripts/check-invariants.mjs`가 막아요.

어긋남이 표에 없으면: 요구사항 정의서 → 개발 문서(data-contract → demo-flow·routes·events·spec-p0 → 정할 것) → UX 설계서 → boundary '추천안' 순으로 따라요. 그래도 안 정해지면 만들지 말고 물어요.

시트 머리말의 두 문장은 옛 방침이에요. 1차에서는 이렇게 읽어요.
- '정할 것' 탭의 "이 탭은 저장소로 내보내지 않아요" → 1차는 이 탭의 **잠정값을 기준으로** 만들어요. 결정 칸이 비어 있어도 잠정값대로 해요.
- '1차 점검' 탭의 "하네스 입력 문서가 아니라 결과 확인용" → 만들 때 기준으로 삼지는 않지만, **W마다 끝났는지 확인할 때** 해당 QA 줄로 스스로 점검해요(`docs/PLAN.md`).

## 아직 안 정해진 것을 만났을 때

- 요구사항 정의서 '미결 사항'(Q-xx)과 개발 문서 '정할 것'에 **잠정값이 있으면 그대로** 만들어요.
- 잠정값도 없으면 만들지 말고 멈춰서 물어요. 물을 때는 무엇이 어긋나는지와 고를 수 있는 안 두세 개를 같이 적어요.
