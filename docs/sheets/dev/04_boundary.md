# 개발 문서 · boundary

> 원본은 Google 시트 '개발 문서'의 'boundary' 탭이에요. `scripts/sheets_to_md.py`가 만든 파일이라 직접 고치지 않아요.

11.16 경계 합의 및 MVP 준비 회의의 결과를 옮긴 문서예요. 누가 무엇을 정하는지, 항목마다 무엇이 정해졌고 무엇이 남았는지를 적었어요. 회의의 한 줄 요약은 '전부 보류'예요. 회의록에 상태가 적히지 않은 항목은 '기록 없음'으로 쓰고 보류로 뒀어요. 추천안은 혜린 초안이라 정모님 의견으로 바뀔 수 있어요.

## 1. 누가 무엇을 정하나

| 담당 | 정하는 것 | 예 |
| --- | --- | --- |
| 혜린 | 화면에 어떻게 보이고, 사람이 무엇을 누르는지 | 밑줄 모양, 카드 배치, 버튼과 문구, 상태별 모양 |
| 정모 | AI가 언제, 무엇을, 어떻게 만드는지. 지면을 어떻게 그리는지는 P 항목에서 확인 | 분석 시점·범위, 제안 내용·수정 이유, 위치 다시 계산과 무효 처리 |
| 함께 | 둘 사이를 오가는 데이터와 이름 | 제안 데이터 형식, 상태 이름, 동작 이름 |

## 5. 충돌 방지 규칙

| 번호 | 규칙 |
| --- | --- |
| 1 | 화면은 데이터를 직접 다루지 않고 data/ 어댑터만 거친다. 목업과 HTTP 전환은 환경 변수로 한다 |
| 2 | ID는 처음부터 브라우저에서 UUID로 만든다. 서버를 붙여도 ID를 바꾸지 않는다 |
| 3 | 원고는 처음부터 편집기 문서에 문단 id(A2, P1)를 붙여 저장한다 |
| 4 | 상태 전이(AI 제안, 장, 수정 제안, 의견)는 화면 밖 순수 함수로 두고 테스트한다. 백엔드로 옮길 때 같은 테스트 케이스를 쓴다 |
| 5 | 이벤트는 처음부터 최종 형식으로 기록하고, 보내는 곳만 나중에 바꾼다 |
