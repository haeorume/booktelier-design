# 화면 그림 (참고용)

> **최종 MVP에서 화면 모양의 기준은 `DESIGN.md`(이 폴더)와 `web/src/styles/tokens.css`예요.** `specimen.html`은 토큰으로 그린 작업 공간 견본이에요(브라우저로 열어 1440·1280px에서 확인).
> 아래 FigJam 그림 4장은 **1차 기준**이에요(옛 종류 이름, 패널 A안만). 배치가 다르면 DESIGN.md와 UX 2 IA를 따라요. 고칠 곳은 UX 'FigJam 그림' 탭 G열.

화면이 **어디에 무엇이 놓이는지** 볼 때만 열어요. 무엇이 있고 어떻게 동작하는지는 시트 문서가 기준이에요.
그림과 글이 다르면 `docs/DECISIONS.md` → 시트 순으로 따라요. 그림은 고치지 않아요.

원본은 FigJam 보드 '북틀리에 UX 설계 (261117)' https://www.figma.com/board/Kj3agAXAFEFFpN1GsYIJPk (11.18 17시에 내보냄)

## 그림이 지금 결정과 다른 곳

| 그림 | 다른 곳 | 따를 것 |
| --- | --- | --- |
| 화면 흐름도 | 종류 이름이 옛 이름(교정·교열·윤문). 카드, 거르기, 장 검토 요약에 나옴 | 맞춤법·띄어쓰기·표기 통일·윤문 넷(D-04, FR-24) |
| 화면 흐름도 | 오른쪽 패널을 '하나씩'만 그림(조판 설정을 열면 검토 패널 자리를 씀) | '나란히'도 만들고 개발용 막대로 바꿈(D-10) |
| 화면 흐름도, 정보구조도 | 보기 전용 링크·'보' 칸(점선, ?) | 1차에는 보기 전용 역할이 없음(D-02) |
| 정보구조도 | 점선 상자(P1: 책 거르기, 저장 상태, 장 추가, 결과 요약, 표기 원칙 탭, 링크 쓸 수 없음) | 2차이거나 밀리면 빼는 것. 범위는 요구사항 정의서 릴리스 칸과 `docs/PLAN.md` |
| 상태 변화도 | 상태를 화면 이름(대기, 적용됨…)으로만 그림. '미검토' 화살표(X-21, X-23) | 코드 값은 data-contract 확정 값(D-05). 미검토 화살표는 잠정값 |

UX 설계서 'FigJam 그림' 탭의 '잠정으로 그린 부분' 칸(겹친 밑줄 모두 표시, 11단계)은 그림보다 옛날 메모예요. 그림은 이미 밑줄 하나와 13단계로 고쳐져 있어요.
